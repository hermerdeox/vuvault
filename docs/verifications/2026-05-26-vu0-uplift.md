## Known residual gap (Tier-3+ closure required)

The OPAQUE handshake (`/api/opaque/register/request`,
`/api/opaque/login/ke1`) inherently requires SOME stable per-account
identifier so the server can load the OPAQUE envelope. In this
build:

- The user-chosen `clientId` is no longer required — clients
  derive a stable handle from `accountSeed` for the lookup.
- During the handshake, that handle reveals "this is account X" to
  the server. Subsequent requests use capability handles that
  rotate per AKD epoch, so the post-handshake session is
  unlinkable.

Full per-handshake unlinkability requires a zero-knowledge proof
layer where the client proves "I know an accountSeed whose handle
is in the current AKD leaf set" without revealing which one. That
is Tier-3+ territory (formal-verification + audit + likely
SNARK-based) and out of scope for this Vu0 build.

The honest Vu0 framing in `docs/PRIVACY-LEVEL.md`:

> **"After OPAQUE login, the server cannot link a session's
> subsequent requests to the account that logged in."**

### Working vault flows (verified by automated tests)

- **Vault provisioning** (`provisionVault`) — fresh v3 vault with `accountSeed` minted.
- **Lock + unlock round-trip** — `lockSession` → `openVault` recovers items, AES key, and accountSeed identically.
- **Save + open items** — round-trip identity preserved; ciphertext length is bucketed.
- **Save + open documents** — round-trip identity preserved; bucketed ciphertext; v1 marker survives the v0 legacy path.
- **Master Password rotation** (`rotateAuth` with master-password key) — re-encrypts vault under new vaultKey; preserves accountSeed and items.
- **Recovery via Recovery Envelope** (`openVaultWithRecoveryEnvelope`) — master password + Secret Key opens vault on any device with the local envelope; preserves accountSeed.
- **Session token rotation** — Bearer tokens rotate via Next-Token on `/api/v2/sessions/self`.
- **Capability minting** (`mintCapability`) — VOPRF round-trip + commit; capability is cached per-epoch in module scope.
- **V2 blob/inv routes via capability** — full PUT/GET/DELETE working through `X-Vu0-Capability` header.
- **AKD epoch publication** — `mintEpoch` builds the Merkle tree, signs the root, persists leaves; `/api/akd/epochs/latest` returns the metadata; `/api/akd/proof/<handle>` returns inclusion proofs.

### Recovery methods verified

The Vu0 implementation MUST preserve all existing recovery
methods. Each is exercised by an automated test:

1. **Master Password recovery via Recovery Envelope.** Test:
   `tests/integration/account-seed.spec.ts > Phase C · Recovery
   Envelope preserves accountSeed`. The Argon2id-derived recovery
   key unwraps the vault AES key; the AES key opens the v3 padded
   vault; the encrypted vault contents (items) and the account row
   (accountSeed, formatVersion) are all preserved. **No change to
   the Recovery Envelope code was needed** — accountSeed lives in
   the Dexie account row, which the envelope leaves untouched.

2. **Master Password rotation** (`rotateAuth`). Test:
   `src/lib/services/vault-session.test.ts > rotateAuth (Milestone
   2 master password)`. Re-encrypts the vault under a new
   vaultKey; preserves all items + accountSeed; preserves the v3
   padded format.

3. **Quick unlock** (`quick-unlock.ts`). Test:
   `src/lib/services/quick-unlock.test.ts` (6 tests). Caches the
   Secret Key under a WebAuthn-PRF-derived key for faster repeat
   unlocks. Unaffected by Vu0 changes (operates on Secret Key
   alone, not accountSeed).

4. **Session lock + zeroize** (`lockSession`). Test:
   `src/lib/services/vault-session.test.ts`. Drops `vaultKey`,
   `aesKey`, and the session token. The persisted `accountSeed`
   stays in Dexie (it's not in memory; it gets re-read on
   unlock).

5. **Auto-lock on idle / hidden tab / pagehide** (`auto-lock.ts`).
   Test: `src/lib/services/auto-lock.test.ts` (5 tests). Triggers
   `lockSession` on idle thresholds.

## Merge sequence for the Vu0 level flip

Mirrors the Vu1 pattern documented in
[`docs/verifications/2026-05-22-vu1-uplift.md`](./2026-05-22-vu1-uplift.md):

```bash
# 1. Push the Vu0 level-flip branch.
git push -u origin vu0-level-flip

# 2. Trigger the CI probe job for this branch.
gh workflow run vu1-probe-e2e --ref vu0-level-flip

# 3. Wait for it to complete; download the artifact.
gh run download --name vu1-probe-passed-${SHA} --dir .

# 4. Verify every v0_c* AND v1_c* = pass.
cat .vu1-probe-passed

# 5. ONLY IF step 4 shows all SIX criteria = pass:
gh pr create --base main --head vu0-level-flip \
  --title "chore(privacy): flip CURRENT_LEVEL 1 → 0 (Vu0 closure)" \
  --body "Closes V0-C1, V0-C2, V0-C3. See docs/verifications/2026-05-26-vu0-uplift.md."

# 6. Merge the PR.
```

The `release.yml` gate enforces the v0_c* check automatically on
every subsequent deploy of `CURRENT_LEVEL=0` sources.
