# Vu Level 1 closure verification — §L07b live wiring + honest flip

**Date:** 2026-05-31
**Authority:** `docs/VU-LEVEL-MIGRATION-MAP.md` (V1-C1/C2/C3);
plan `vu-level-migration-temporal-wind.md`
**Scope:** the deferred §L07b wiring (V1-C1, V1-C3), retirement of the
legacy per-account transport, the probe upgrade from shape to behavior,
and the honest `CURRENT_LEVEL` 2 → 1 flip.

## TL;DR

The earlier 2026-05-22/24 uplift built the Vu Level 1 infrastructure —
random-UUID v2 blob/inventory routes, the `blob-inventory.ts` crypto
primitives, the `uploadV2Blob`/`fetchV2Blob`/`uploadV2Inventory`/
`fetchV2Inventory` client helpers — but **never connected it to the
live data path**, while authoring docs that called V1-C1/C3 "CLOSED".
The running client still synced the whole vault and every document to
the legacy per-account routes (`vaults/{accountId}/…` in R2), so a
server could still enumerate an account's blobs (V1-C1 open) and order
writes across accounts via the `sequence_clock` columns (V1-C3 open).
The shape-only release probe passed anyway because it only asserted that
the v2 routes *exist* and that error bodies name no `account_id` — never
that the client had *stopped using* the leaky routes.

This pass finishes the deferred wiring and flips the level honestly:

1. **V1-C1 / V1-C3 wired into the live path.** Whole-vault save/restore
   and document attach/read now write random-UUID blobs at
   `/api/v2/blobs/<uuid>` (no account prefix) with the latest-pointer in
   a client-side encrypted inventory at `/api/v2/inv/<addr>` whose
   address the passive server cannot compute.
2. **Legacy per-account transport deleted.** `/api/blobs/upload`,
   `/api/blobs/latest`, and `/api/documents/[blobId]` are gone; the
   server no longer has a per-account blob path to enumerate.
3. **Server sequence clock dropped** (`migrations/0009_drop_sequence_clock.sql`).
   Write ordering is now a client-only inventory index.
4. **Probe upgraded from shape to behavior** — it now asserts the
   deleted routes return no handler, and the e2e flow asserts (via
   request interception) that real saves/documents touch only v2.
5. **`CURRENT_LEVEL` flipped 2 → 1**, with the Level 1 claim scoped
   honestly (see "What V1 does and does not claim" below).

## What changed in the live data path

| Flow | Before (leaky) | After (V1) |
| --- | --- | --- |
| Whole-vault push | `uploadBlob` → `/api/blobs/upload` → `vaults/{accountId}/{N}.bin` | `uploadV2Blob` (random UUID) + `inventorySetVaultBlob` → `/api/v2/blobs/<uuid>` + `/api/v2/inv/<addr>` |
| Whole-vault pull | `fetchBlob` → `/api/blobs/latest` (per-account) | `inventoryPullVault` → `fetchV2Blob` |
| Document attach | `uploadDocumentBlob` → `/api/documents/<blobId>` → `vaults/{accountId}/documents/…` | `uploadV2Blob` + `inventoryAddDocumentBlob` |
| Document read | `fetchDocumentBlob` (per-account) | `fetchV2Blob` |
| Document purge | `deleteRemoteDocumentBlob` (per-account) | `inventoryRemoveDocumentBlob` + `deleteV2Blob` |
| Recovery re-seal | per-account re-upload | `uploadV2Blob` + inventory rebuild in `rebindRecoveredVault` |

Wiring evidence (live, not orphaned):

- `src/lib/services/vault-session.ts` — `pushBlobToServer`
  (`uploadV2Blob` / `inventorySetVaultBlob` / `deleteV2Blob`),
  `pullBlobFromServer` (`inventoryPullVault` / `fetchV2Blob`),
  `rebindRecoveredVault` (v2 re-seal loop).
- `src/lib/services/document-blobs.ts` — `attachDocumentFile`
  (`uploadV2Blob` / `inventoryAddDocumentBlob`), `readDocumentBlob`
  (`fetchV2Blob`), `purgeDocumentBlob` (`inventoryRemoveDocumentBlob` /
  `deleteV2Blob`).
- `src/lib/services/inventory-session.ts` — session-scoped inventory
  manager over `blob-inventory.ts` primitives; `inventoryLatestIndex`
  supplies the client-only monotonic save counter that replaces the
  dropped server `sequence_clock`.
- No remaining imports of the deleted v1 helpers (`uploadBlob`,
  `fetchBlob`, `uploadDocumentBlob`, `fetchDocumentBlob`).

## V1-C1 / V1-C2 / V1-C3 — closed

- **V1-C1 (no per-user blob inventories) — CLOSED.** Blobs are keyed by
  random UUID with no account prefix; the only per-account-shaped state
  (the latest-pointer) lives in a client-side **encrypted** inventory at
  an address the passive server cannot derive. The legacy per-account
  R2 prefix is deleted, so the enumeration surface no longer exists.
- **V1-C2 (no persistent device set) — CLOSED** (unchanged from the
  2026-05-22 Phase 2 work). `migrations/0004_metadata_minimization.sql`
  drops `sessions.device_id`, `accounts.last_login_at`, and the
  `device_pairings` table, with a guard trigger; KE3 writes no device
  fields.
- **V1-C3 (no cross-account sequence-clock correlation) — CLOSED.**
  `migrations/0009_drop_sequence_clock.sql` drops
  `accounts.sequence_clock` and `sessions.sequence_clock`. Ordering is
  now a client-only inventory index that never reaches the server.

## What V1 does and does not claim

**Claimed at Vu Level 1:** E2E content (vault items + document bytes) +
minimized relay metadata — no per-user blob inventory, no persistent
device set, no cross-account sequence clock.

**Accepted residual (Candidate 1 — explicitly accepted here).** The
inventory bootstrap address is `bootstrapAddress(vaultKey, deviceSalt)`,
a deterministic HKDF of the secret vault key. A party who already holds
`vaultKey` can recompute the address and confirm an inventory exists —
but that is moot, since holding `vaultKey` already discloses the entire
vault. The passive server, lacking `vaultKey`, sees only writes to one
opaque `/api/v2/inv/<addr>` with no account linkage. No prior human
sign-off for this acceptance was actually on record (despite comments in
`blob-inventory.ts` implying one); this document is the explicit
acceptance. Replacing the deterministic address with blinded/unlinkable
routing is a **Vu Level 0** (V0-C1) item, not required for V1.

**NOT claimed at Vu Level 1 (Tier-2 futures, still pending/partial in
the evidence map):** field-level CRDT sync (E11), bucketed-padding
deltas (E12, partial), MLS sharing (E13), AKD-anchored device pairing,
and PIR breach checks (E15). Marking any of these "shipped" would be
dishonest and is not required to hold the V1 invariant set.

## Honesty note

Unlike the 2026-05-22 report (annotated with a correction banner), the
closure recorded here is verified **behaviorally**: the probe's negative
assertion proves the leaky routes are gone, and the e2e request
interception proves the live client uses only v2. The level flip is
therefore backed by what the running app does, not only by what the
infrastructure could do.
