# Vu1 uplift verification report — multi-phase synthesis

> **⚠️ 2026-05-31 correction — read first.** This report's claim that the
> **V1-C1 + V1-C3 closure** "shipped" in the 2026-05-24 Phase 4 update was
> **premature**. The per-blob random-UUID v2 routes, the client inventory
> primitives (`blob-inventory.ts`), and the v2 sync helpers were built and
> unit-correct, but they were **never wired into the live save/restore or
> document path** — `vault-session.ts` and `document-blobs.ts` still synced
> to the legacy per-account routes (`/api/blobs/*`, `/api/documents/*`).
> The local probe passed only because it asserted route **shape**, not that
> the client had **stopped using** the leaky path, so a running server could
> still enumerate per-account blobs and order writes across accounts. V1-C1
> and V1-C3 were therefore **infrastructure-complete but NOT closed** as of
> this report, and the `CURRENT_LEVEL` flip on the `vu1-level-flip` branch
> would have claimed Vu Level 1 while the leak was live. The actual live
> closure — wiring the v2 path into the production save/restore + document
> flows, deleting the legacy routes, dropping the server-side sequence
> clock (migration 0009), and upgrading the probe to a behavioral negative
> assertion — landed 2026-05-31 and is recorded in
> [`2026-05-31-vu1-closure.md`](./2026-05-31-vu1-closure.md). **V1-C2**
> (Phase 2) was genuinely closed here and is unaffected by this correction.

## Merge sequence for the level-flip

The level-flip commit (`e0ec761`) sits on the `vu1-level-flip`
branch. The user-action sequence to merge it:

```
# 1. Push the branch.
git push -u origin vu1-level-flip

# 2. Trigger the CI probe job for this branch.
gh workflow run vu1-probe-e2e --ref vu1-level-flip

# 3. Wait for it to complete; download the artifact.
gh run download --name vu1-probe-passed-${SHA} --dir .

# 4. Verify every v1_c*=pass.
cat .vu1-probe-passed
#    sha=<vu1-level-flip HEAD SHA>
#    v1_c1=pass
#    v1_c2=pass
#    v1_c3=pass
#    (v0_c1 and v0_c2 still expected_fail — informational only)

# 5. ONLY IF step 4 shows all three V1-C* = pass:
gh pr create --base main --head vu1-level-flip \
  --title "chore(privacy): flip CURRENT_LEVEL 2 → 1 (Vu1 closure)" \
  --body "Closes V1-C1, V1-C2, V1-C3. See docs/verifications/2026-05-22-vu1-uplift.md."

# 6. Merge the PR.
```

The release.yml gate enforces case (2) automatically: any
post-merge deploy whose source carries `CURRENT_LEVEL=1` MUST
also carry a green probe artifact, or the deploy fails closed.

When CI runs against any subsequent push, the artifact will
be tagged with the actual `GITHUB_SHA` and uploaded under
`vu1-probe-passed-${SHA}`. The `release.yml` gate then downloads
that artifact and enforces it based on the repo's `CURRENT_LEVEL`.
