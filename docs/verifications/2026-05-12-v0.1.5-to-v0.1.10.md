## Per-Release Findings

### `v0.1.5` — Mobile + Performance

**Static.** `vite.config.ts` sets `build.sourcemap` to `'hidden'` by default and pins heavy dependencies into `vendor-noble-pq`, `vendor-noble-ciphers`, `vendor-noble-core`, `vendor-opaque`, and `vendor-dexie` chunks. `src/lib/utils/env.ts` verifies bundle chunks with `Promise.all`. `src/app.html` preloads the two Latin first-paint font subsets. `src/lib/styles/fonts.css` keeps JetBrains Mono to Latin only.

**Runtime.** `npm run test:e2e -- tests/e2e/mobile-responsive.spec.ts --workers=1` passed `13/13` after this pass. The spec covers viewport tagging, no horizontal overflow, the cardinal no-body-scroll rule, landing mobile panel reflow, and the new rendered touch-target floor.

**Adversarial.** I added a rendered 44×44 CSS-pixel measurement over `.ico-btn`, `.add-btn`, `.lock-btn`, `.overflow-trigger`, mobile tabs, shared modal `.close`, `Button`, and command-palette rows. This locks the ROADMAP’s WCAG 2.5.5 mobile claim to actual DOM geometry instead of CSS inspection.

**Gap.** `v0.1.5` has a remote tag (`c9e16d9f...`) and a failed CI push run, but no GitHub Release and no `release.yml` event. Backfilling it would redeploy an old tag, so this remains documented as a historical publication gap.

### `v0.1.6` — Release Prep + Drift

**Static.** `src/lib/utils/env.tamper.test.ts` still covers six bundle tamper modes. `wrangler.toml` had top-level `PUBLIC_BUNDLE_HASH` and `PUBLIC_SYNC_ORIGIN` while production intentionally omitted them for release-time injection.

**Runtime.** Targeted Vitest suite passed: `env.tamper.test.ts`, `api-routes.spec.ts`, `worker.spec.ts`, `opaque-client.test.ts`, `sync-client.test.ts`, and `vault-session.test.ts` all green (`71` tests).

**Adversarial.** I hardened `scripts/audit-bindings.mjs` with a new Rule 0 that fails any var present in `[vars]` but missing from `[env.production.vars]`, then removed the two placeholder top-level vars from `wrangler.toml`. `node scripts/audit-bindings.mjs` now reports `OK (2 Env bindings × 2 envs verified, 5 vars tracked)` with no Wrangler inheritance warning source left.

### `v0.1.7` — Landing Hydration + URL Literal

**Static.** `tests/e2e/landing.spec.ts` waits for `waitForLandingHydration()` before keyboard/pager/audience interactions.

**Runtime.** `npm run test:e2e -- tests/e2e/landing.spec.ts --workers=1` passed `13/13`.

**Adversarial.** A shipped landing-source URL sweep now finds no `http(s)://` literals under `src/routes/(landing)`. The audit found one remaining `https://github.com/vuvault` href in `Final.svelte`; I replaced it with same-origin blueprint links and converted the panel to SvelteKit `resolve()` links. `npx @sveltejs/mcp svelte-autofixer src/routes/(landing)/_panels/Final.svelte` reports no issues.

### `v0.1.8` — Hidden M3 Artifact

**Static.** The single-line change adds `include-hidden-files: true` to the M3 artifact upload for `.m3-e2e-passed`.

**Runtime.** The `v0.1.8` release workflow completed successfully. Its job steps include successful `Download M3 D1/R2 E2E artifact`, `Verify production runtime configuration`, `Deploy to Cloudflare Pages`, and `Post-deploy production smoke`.

**Adversarial.** The previous `v0.1.6`/`v0.1.7` failures both died at `Download M3 D1/R2 E2E artifact`; `v0.1.8` proves the hidden-file upload fix closed that gate.

### `v0.1.9` — D1 Rate Limit + OPAQUE Restore

**Static.** `src/lib/server/api/rate-limit-d1.ts` implements atomic D1 upsert counters with fail-closed `503` on limiter storage errors. `src/routes/api/opaque/register/request/+server.ts` calls it before request parsing. `src/lib/services/opaque-client.ts` forces the JS OPAQUE backend with `setBackend(...)`.

**Runtime.** Targeted Vitest passed `71` tests, including D1/API handlers, stable D1-backed OPAQUE identity, browser-compatible OPAQUE client, sync-client error decoding, and vault-session sync fallback.

**Adversarial.** A live 12-request burst against `https://vuvault.app/api/opaque/register/request` returned `[429 × 12]`, proving the limiter is active in production. `api-routes.spec.ts` separately simulates D1 limiter table failure and expects `503 rate limiter unavailable`.

**Release note.** The original `v0.1.9` release workflow failed only at post-deploy smoke because the HTTP CSP header was missing. The API/rate-limit changes themselves are verified in `v0.1.10`, which includes this release’s code.

### `v0.1.10` — HTTP CSP

**Static.** `_headers` now emits a production CSP, HSTS, `nosniff`, `DENY` framing, no-referrer, permissions policy, COOP, and CORP.

**Runtime.** Fetching `https://vuvault.app/` returns a CSP containing `object-src 'none'`, `frame-src 'none'`, and `upgrade-insecure-requests`. A Playwright Chromium probe loaded the live page, confirmed `document.documentElement.dataset.hydrated === 'true'`, and observed no page errors.

**Adversarial.** The same browser probe injected `https://evil.example.com/vuvault-csp-probe.js`; Chromium blocked it with CSP console violations from both the HTTP header and SvelteKit meta CSP. The `v0.1.10` release workflow reports success for `Verify production runtime configuration`, `Deploy to Cloudflare Pages`, and `Post-deploy production smoke`.

## Outstanding Issues

1. `v0.1.5` was tagged but never published as a GitHub Release. Do not backfill unless you explicitly want the release workflow to run against that old tag.
2. `npm run lint` and `npm run check` still print existing warnings unrelated to this audit: brand generation unused vars, `SplashScreen.svelte` `any`, shared landing CSS unused selectors, `TechDrawer.svelte` initial prop capture, and `ItemEditor.svelte` `text-security`.
3. The current CSP allows `'unsafe-inline'` at the HTTP layer to preserve SvelteKit bootstrap compatibility. SvelteKit’s prerendered meta CSP still emits hashes, but future work can tighten the HTTP header once inline bootstrap handling is fully deterministic.
